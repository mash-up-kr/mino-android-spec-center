MASC Discord 알림 — 상황별 메시지 미리보기

웹훅 MASC 알림이 보내는 실제 payload를 그대로 재현했습니다. 역할 멘션은 embed 밖 본문(content)에 들어가 실제로 핑이 울리고, 제목을 클릭하면 대시보드의 해당 feature(또는 PRD)로 이동합니다.

트리거는 셋입니다 — 1–5는 spec 파이프라인 상태 전이(notifyOnFeatureWrite), 6–9는 상위 문서 PRD의 등록·개정(notifyOnPrdWrite), 10은 PRD 논의의 @멘션(notifyOnPrdComment)입니다.

상위 문서 트랙

여기부터는 spec의 상위 문서인 PRD(docs/prd/business-context.md · 프로젝트당 1개) 알림입니다. PRD는 제품 전체 문서라 등록·MAJOR·MINOR는 4개 역할 전부(Android·Design·iOS·Node)를 태그합니다 — 안드로이드 spec만 다루는 위 파이프라인 알림과 대상이 다릅니다. PATCH·본문 갱신은 멘션하지 않습니다.

PRD 논의 @멘션

PRD 댓글은 @멘션이 포함된 것만 알립니다(일반 댓글은 소음). 역할 핑은 하지 않고 본문 300자까지, 섹션 앵커가 있으면 필드로 붙습니다. 멘션 토큰은 GitHub 핸들이라 대시보드에서 @ 자동완성 드롭다운으로 골라야 잡힙니다 — 한글 이름을 직접 타이핑하면 이 알림이 발송되지 않습니다.

섹션
1. 서비스 개요 및 개발 방향
알아둘 것
  • status가 바뀌지 않는 저장(본문 수정, 보충 코멘트, 사유 편집)과 PR 생성 / PR 미머지 종료 전이는 알림이 가지 않습니다.
  • PRD 쪽 가드도 같은 원리입니다 — 버전이 그대로이고 본문도 동일한 쓰기(버전 메모 편집 등)는 조용히 종료됩니다.
  • iOS·Node는 PRD 알림에만 붙습니다. spec 파이프라인은 MASC가 안드로이드 spec만 다루므로 Android/Design 그대로입니다. 동봉되는 "뒤처진 spec 목록"도 features 기준이라 안드로이드 spec만 나옵니다 — iOS·Node는 "PRD가 바뀌었다"는 신호를 받고, 후속 조치는 각 팀 레포 소관입니다.
  • 멘션 색은 실제로는 서버 역할 색을 따릅니다 (Android 초록, Design 보라 — iOS·Node 색은 이 페이지의 임의 표현입니다).
  • 역할 설정에서 "누구나 이 역할을 @mention할 수 있음"이 꺼져 있으면 텍스트는 보이지만 핑이 울리지 않습니다.
  • 작성자·개정자 필드는 Firestore users(PRD는 헤더 표의 최종 수정자)를 따르고, 조회 실패 시 필드만 빠진 채 발송됩니다.
  • 개인 <@id> 멘션은 아직 없습니다 — users.discordId 매핑 후 Tier 2입니다. PRD 논의 멘션도 채널 알림 제목에 핸들을 적는 방식입니다.
