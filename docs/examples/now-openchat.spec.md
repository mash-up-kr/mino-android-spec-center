## 1. 유저 시나리오 (User Scenarios) *(필수)*

### 유저 플로우 1 - 오픈채팅 목록 진입
참여 중인 오픈채팅방을 핀 고정 최상단 + 최근 활동 순으로 확인한다.

**Figma**: [오픈채팅 목록](https://www.figma.com/design/xxxx?node-id=2001-0001) · [빈 상태](https://www.figma.com/design/xxxx?node-id=2001-0003)

**진입 조건**: "지금" 탭에서 오픈채팅 세그먼트를 선택한 상태

1. 오픈채팅 세그먼트 선택 → 스켈레톤 리스트를 그리고 목록을 요청한다
2. 목록 응답 도착 → 핀 고정 방을 최상단에, 나머지를 마지막 메시지 시각 내림차순으로 배치한다
3. 참여 방이 없음 → 안내 문구와 "오픈채팅 탐색" 버튼을 표시한다

**완료 조건**: 참여 중인 방 목록이 정렬 규칙대로 화면에 표시된다

### 유저 플로우 2 - 채팅방 진입
목록에서 방을 선택해 채팅방으로 이동한다.

**완료 조건**: 선택한 방의 채팅방 화면이 표시되고 안읽음 배지가 0이 된다

## 2. 요구사항 (Requirements) *(필수)*

### 2.1 기능적 요구사항 (Functional Requirements)

- **FR-001**: 시스템은 반드시 참여 중인 오픈채팅방 목록을 안읽음 수와 함께 표시한다. (근거: Figma 2001-0001)
- **FR-002**: 시스템은 반드시 핀 고정 방을 최상단에 두고 나머지를 마지막 메시지 시각 내림차순으로 정렬한다. (근거: Figma 2001-0001)
- **FR-003**: 시스템은 반드시 참여 중인 방이 없을 때 안내 문구와 탐색 진입 버튼을 표시한다. (근거: Figma 2001-0003)
- **FR-004**: 시스템은 반드시 목록 조회 실패 시 에러 문구와 재시도 수단을 제공한다. (근거: Figma 2001-0004)
- **FR-005**: 시스템은 반드시 방 항목 선택 시 해당 채팅방으로 이동시킨다. (근거: Figma 2001-0010)

### 2.2 핵심 UX 규칙 (Core UX Rules)

- **UX-001**: 목록을 기다리는 동안 스켈레톤 리스트를 표시하고 중복 요청을 막는다. (근거: Figma 2001-0002)
- **UX-002**: 안읽음 개수가 300을 초과하면 "300+"로 표기한다. (근거: Figma 2001-0001)
- **UX-003**: 새 메시지 수신으로 정렬이 바뀌어도 사용자가 스크롤 중이면 위치를 강제로 되돌리지 않는다. (근거: Figma 2001-0001)

### 2.3 주요 도메인 (Core Domain)

- **오픈채팅방**: 방 식별자, 제목, 썸네일, 마지막 메시지와 시각, 안읽음 수, 핀 고정 여부
- **참여 목록**: 사용자가 참여 중인 오픈채팅방의 모음. 정렬 기준 데이터를 함께 가진다

## 3. 범위 (Scope) *(필수)*

### 3.1 측정 가능한 성과 (Measurable Performance)

- **SC-001**: 세그먼트 진입 후 1초 이내에 목록 첫 화면이 표시된다
- **SC-002**: 새 메시지 수신 후 3초 이내에 목록 순서가 갱신된다
- **SC-003**: 사용자의 90%가 첫 시도에 원하는 방으로 진입한다

### 3.2 비목표 항목 (Out of Scope)

- 오픈채팅방 생성·나가기 흐름은 별도 스펙이 정의한다
- 채팅방 내부 메시지 렌더링 규칙은 이 문서가 정의하지 않는다
- 실시간 갱신 전송 방식(폴링·WebSocket·FCM)은 서버가 정의한다

## 4. 가정 (Assumptions)

- 사용자는 안정적인 네트워크 환경에 있다
- 참여 중인 방 목록은 서버가 정렬 기준 데이터를 함께 내려준다
- 기존 인증 세션을 재사용한다
